## 3. Technology findings (why the port is config-centric)

EF6 6.5.1 code-first on .NET Framework 4.8, LINQ-only data access. Audit found **zero** raw SQL (`SqlQuery`/`ExecuteSqlCommand`/`FromSqlRaw`), **zero** stored procedures, **zero** ADO.NET call sites (`SqlConnection`/`SqlCommand`/`SqlDataReader`), **zero** `TransactionScope`, **zero** `catch` blocks, **zero** bulk paths, **no** NOLOCK, **no** MARS-dependent code (no `virtual` navigation properties → no lazy loading), **no** full-text/temporal/synonyms/partitioning/cross-db references. Graphify call-graph cross-check (`explain ApplicationDbContext`) confirmed the data-access set was complete. Consequently the §2 seams (`ISqlDialect`, `ISqlQueryProvider`, `IBulkInserter`, `IDbConnectionFactory`) have no consumers: creating them would be empty scaffolding (R10); the one live seam is provider resolution + EF6 provider/model selection, implemented below.

## 5. "No equivalent" flags (§8) — each with options, none approximated silently

1. **`[Timestamp] byte[] RowVersion` concurrency token** (`app/Bookstore.Domain/Entity.cs`, every entity) — SQL Server `rowversion` has no PostgreSQL equivalent, and EF6 cannot map an `xmin` system-column token (that is EF Core-only). PG branch leaves the column unmapped; optimistic-concurrency checking is therefore **inactive on PostgreSQL** (silent-writer conflicts surface as last-write-wins). Options considered: (a) ignore the token on PG *(taken — no schema change, SQL Server unchanged)*; (b) add an explicit `integer`/`bigint` version column on both engines — rejected: a logical schema change, forbidden by `allow_schema_changes=false`; (c) migrate this path to EF Core to use `xmin` — out of scope.
2. **Case-sensitivity of string search** (`BookRepository.cs`, `OfferRepository.cs` `Contains(...)`; `Sub ==` comparisons in `CustomerRepository`/`AddressRepository`/`OrderRepository`) — SQL Server resolves `LIKE`/`=` under a case-insensitive collation; PostgreSQL `LIKE`/`=` are case-sensitive (B6/B7). EF6 LINQ offers no per-provider `ILIKE` translation hook, and R2 forbids query rewrites. On PostgreSQL, name/author/ISBN searches become case-sensitive. Options: (a) accept the stricter behavior *(taken — flagged, no code change)*; (b) `citext` columns — schema change, forbidden; (c) per-provider `lower()` expression fork — a query-semantics change R2/R8 discourage; revisit with the client if search parity is contractual.
3. **`Integrated Security=SSPI` / LocalDB** (`Web.config`) — Windows auth has no Npgsql analog; a PG deployment needs SCRAM credentials in `BookstoreDatabaseConnection_PostgreSql`. Infrastructure prerequisite, not a code change.
4. **`MultipleActiveResultSets=true`** (SQL Server string only) — no Npgsql equivalent (§5.8); retained for SQL Server (R1) and absent from the PG string. Code audit found no reader-iteration pattern that depends on MARS.

## 8. Rollout prerequisites (§9 item 11 and runbook items)

1. **pg_version 16 assumed** — undeterminable from the repo; pin the real target before relying on any version-gated behavior. (This port writes no version-gated SQL, so the risk is limited to the schema script, which is valid from PG 10.)
2. Provision PostgreSQL ≥ the pinned version; create the database (`createdb "BookStoreClassic"`) and run `db-scripts/bobs-used-bookstore-classic-db-postgresql.sql` — or let EF6's `DropCreateDatabaseIfModelChanges` initializer create the schema on first start (then re-sync identity sequences if seeding manually — the script already does this via `setval`).
3. Fill in real credentials in `BookstoreDatabaseConnection_PostgreSql` (placeholder `[PLACEHOLDER]` shipped — R5); set `Search Path=public` (pooled sessions reset session-level `search_path`).
4. Set `Data/Provider=PostgreSql` per environment (SSM deployments: publish a parameter alongside the existing connection-string parameter); the app fails fast if the key or connection string is missing/invalid.
5. **Concurrent-writer behavior change on PG**: the RowVersion optimistic-concurrency check is inactive (§5 flag 1) — review order/stock update paths for lost-update tolerance.
6. **Search case-sensitivity on PG** (§5 flag 2) — confirm acceptance with the client, or plan the `citext`/`lower()` follow-up.
7. An external pooler in **transaction** mode (e.g. PgBouncer) would need `max_prepared_statements` (PgBouncer 1.21+) or client-side prepared statements disabled — EF6/Npgsql 4 uses server-side prepares; session/statement pooling is unaffected here but flag it before adding a pooler.
8. AWS/CDK: `DatabaseStack` currently provisions RDS SQL Server only. A PG environment needs a parallel RDS PostgreSQL instance + its connection string in SSM at `/BobsUsedBooksClassic/Database/ConnectionStrings/BookstoreDatabaseConnection_PostgreSql` (and the provider parameter) — not part of this code change.
